# Markdown 語法參考

`scripts/convert_md_to_tex.py` 是自製的轉換器，**只支援下列語法**。它不是完整的 Markdown 實作，也不是 Pandoc — 沒列在「支援」清單裡的語法會被原樣輸出成論文正文中的字面字元。

## 文件結構

一級標題 `#` 有三種角色，由標題文字決定：

| 標題 | 效果 |
|---|---|
| `# 摘要` | 抽成獨立的中文摘要頁（`chapters/abstract_zh.tex`） |
| `# Abstract` | 抽成獨立的英文摘要頁（`chapters/abstract_en.tex`） |
| `# 誌謝` 或 `# 謝辭` | 抽成獨立的誌謝頁（`chapters/acknowledgements_zh.tex`） |
| `# 參考文獻` 或 `# References` | **轉換到此停止**，之後所有內容都被忽略 |
| 其他任何 `#` | 依出現順序成為第一章、第二章……（`chapters/chapter_NN.tex`） |

所以 `markdown/thesis.md` 的建議骨架是：

```markdown
# 摘要 {-}
（中文摘要與關鍵詞）

# Abstract {-}
（英文摘要與 Keywords）

# 誌謝 {-}
（謝辭）

# 第一章　緒論 {#c:intro}
...
# 第二章　文獻探討 {#c:review}
...
# 參考文獻 {-}
（這行以下的內容都不會進 PDF，書目由 references.bib 自動產生）
```

## 標題

```markdown
# 第一章　緒論 {#c:intro}
## 1.1　研究背景 {#s:background}
### 1.1.1　子題
#### 更細的層級
```

- 支援 `#` 到 `####` 共四級。**`#####` 以上不支援**，會被當成內文印出 `#####` 字元。
- 標題開頭的編號會被自動移除（`第一章`、`1.1`、`1.1.1` 都會被剝掉），由 LaTeX 重新編號。所以你在 Markdown 裡寫的編號只是給自己看的，不會出現在 PDF。
- `{#label}` 設定交叉引用標籤，選用。沒寫的話章會自動得到 `c:chapter-01` 這類標籤。
- `{-}` 這種不含 `#` 的屬性會被忽略，安全。

交叉引用要在 Markdown 裡直接寫 LaTeX：`如\ref{c:intro}所述` — 這類反斜線開頭的內容會原樣通過，但**只有你確定它是合法 LaTeX 時才這樣做**。

## 行內格式

| 語法 | 結果 |
|---|---|
| `**粗體**` | `\textbf{粗體}` |
| `` `程式碼` `` | `\texttt{程式碼}` |
| `$x_i$` | 行內數學，內容原樣送進 LaTeX |
| `[@key]` | `\citep{key}`（括號式引用） |
| `[@a; @b]` | `\citep{a,b}` |
| `@key` | `\citet{key}`（敘述式引用） |

**不支援**（會變成正文中的字面字元）：

- `*斜體*` 與 `_斜體_` → 印出星號本身。要斜體請直接寫 `\textit{文字}`。
- `[文字](網址)` → 印出中括號與圓括號。要超連結請直接寫 `\href{網址}{文字}`。
- `~~刪除線~~`
- `[^1]` 腳註 → 要腳註請直接寫 `\footnote{內容}`。

LaTeX 特殊字元（`% & # _ $ { } ^ ~ \`）會自動跳脫，直接打 `50%` 或 `a_b` 是安全的。

## 清單

```markdown
- 項目一
- 項目二

1. 第一點
2. 第二點
```

兩個限制：

- **不支援巢狀清單。** 縮排的子項目會被拉平到同一層。需要階層就改用 `###` 標題，或直接寫 `\begin{itemize}...\end{itemize}` 手動巢狀。
- **有序清單至少要兩項**才會變成 `enumerate`。只有一項時會被當成普通段落，印出 `1. ` 的字面文字。

## 數學式

行內用 `$...$`。獨立公式用 `$$` 包住：

```markdown
$$
y_i = \alpha + \beta x_i + \varepsilon_i
\tag{1.1}
$$
```

- 含 `\tag{}` → 產生有編號的 `equation` 環境。
- 不含 `\tag{}` → 產生無編號的 `equation*` 環境。
- `$$` 必須各自獨佔一行。
- 公式內容原樣送進 LaTeX，不做任何跳脫，所以裡面要寫合法的 LaTeX 數學語法。

## 圖片

```markdown
![圖 1.1 研究流程](images/research-flow.png){#fig:research-flow}
```

- 圖片必須獨佔一行。
- 圖說開頭的「圖 1.1」「Figure 1.1」會被自動移除（LaTeX 會重新編號），實際 caption 是「研究流程」。
- `{#label}` 選用。沒寫時，若圖說含「圖 1.1」會自動產生 `fig:1-1` 標籤。
- 路徑相對於專案根目錄。`thesis.tex` 的 `\graphicspath` 另外掛了 `markdown/`，所以從 Word 匯入的圖片路徑也能直接用。
- 圖片一律置中、寬度撐滿 `\linewidth`。要指定寬度請改用手寫 `\includegraphics[width=0.6\linewidth]{...}`。

圖說較長時，可以在圖片**下一行**用引言區塊寫完整圖說，它會取代中括號裡的文字：

```markdown
![圖 1.1](images/flow.png)

> **圖 1.1**　研究流程圖。資料來源：本研究整理。
```

## 表格

表格標題寫在表格**正上方**，格式是 `表 1.1 標題` 或 `Table 1-1 Caption`：

```markdown
表 1.1 變數操作型定義

| 變數 | 說明 | 平均數 |
|---|---|---:|
| 感知有用性 | 使用者認為工具有助於完成任務的程度 | 4.21 |
| 慣性 | 維持既有使用方式的傾向 | 3.05 |
```

- 有標題行 → 產生 `\caption` 與 `\label{tab:1-1}`（編號取自標題文字）。
- 沒有標題行 → 仍會產生表格，但沒有 caption 與 label，也不會出現在表目錄。
- 一律使用 booktabs 三線表。

**欄位對齊是自動判斷的**，Markdown 裡的 `:---:` 對齊語法會被忽略：

| 判斷條件 | 對齊 |
|---|---|
| 整欄都是數字（可含 `$`、`%`、`,`、`+`、`-`、`—`） | 靠右 `r` |
| 整欄都是行內數學且標題不長 | 靠左 `l` |
| 標題超過 14 個顯示寬度，或欄內最長值超過 20 | 自動換行欄 `X`（tabularx） |
| 其他 | 靠左 `l` |

有 `X` 欄時整表用 `tabularx` 撐滿頁寬；沒有時用 `adjustbox` 自動縮放以免超出版面。**很寬的表格會被縮到字很小**，這時考慮拆表或改成橫式頁面。

儲存格內容不能包含 `|` 字元。

從 Word 匯入的 HTML 表格（`<table>...</table>`）也支援，`<br>` 會轉成全形分號，`colspan` 會補空欄。

## 其他

| 語法 | 行為 |
|---|---|
| ` ``` ` 程式碼區塊 | 轉成 `verbatim` 環境，內容完全原樣 |
| `> 引言` | 轉成普通段落（除非緊接在圖片下方，見上文） |
| `---` 分隔線 | 直接忽略 |
| 空行 | 保留為段落分隔 |

## 轉換後的檢查

`make convert` 只做 Markdown → LaTeX，不編譯，適合快速檢查轉換結果：

```bash
make convert
less chapters/chapter_01.tex
```

排版不如預期時，**先看 `chapters/*.tex` 判斷問題出在轉換還是 LaTeX**。若轉換結果就已經不對，問題在 Markdown 寫法；若轉換結果正確但 PDF 不對，問題在 `thesisclass.cls` 或 `thesis.tex`。
